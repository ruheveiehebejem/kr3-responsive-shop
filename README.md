# Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

## Описание
Проект основан на HTML/CSS-проекте КР №1 ShopProject. Исходные главная страница, каталог, контакты, основные стили и JavaScript перенесены из репозитория `kr1-html-css-shop-`. Добавлены недостающие страницы товара и заявки и адаптивные стили из практического занятия №12.

Bootstrap в проекте КР №3 не используется.

## Практическая работа №12 — адаптивная вёрстка
- перенесены исходные HTML/CSS/JS-файлы КР №1;
- добавлен отдельный файл `css/responsive.css`;
- на всех пяти страницах добавлен `meta viewport`;
- `responsive.css` подключён после `style.css`;
- применён подход Mobile First и медиазапросы;
- адаптированы шапка и навигация, hero-блок, сетка карточек и каталог с фильтром;
- добавлен элемент `picture` для изображения товара;
- адаптированы форма заявки и таблица характеристик.

В исходном репозитории КР №1 папки `images/` не было. Поэтому добавлен нейтральный SVG-заполнитель `images/product-placeholder.svg`; его можно заменить реальным изображением, сохранив HTML-структуру.

## Практическая работа №13 — доступность
- добавлена ссылка пропуска к основному содержимому (`skip-link`);
- на каждой странице предусмотрен основной заголовок `h1`;
- навигация имеет доступное название, текущая страница помечается `aria-current="page"`;

- таблица содержит `caption`, заголовки и ячейки;
- для таблицы на узком экране предусмотрена горизонтальная прокрутка внутри контейнера.

## Практическая работа №13 — A11y-аудит и Lighthouse

Тема: «A11y-аудит и обеспечение доступности. Использование Lighthouse и анализ проблем доступности».

### Реализованные исправления доступности

- добавлена ссылка пропуска к основному содержимому `skip-link`;
- на каждой странице есть основной заголовок `h1` и основная область `main`;
- основная навигация и хлебные крошки имеют доступные названия;
- текущая страница помечается через `aria-current="page"`;
- добавлен видимый клавиатурный фокус через `:focus-visible`;
- ссылки и кнопки используются по назначению;
- поля форм связаны с подписями `label` через `for` и `id`;
- изображения имеют альтернативные описания `alt`;
- модальное окно главной страницы реализовано через `dialog` и имеет заголовок, связанный через `aria-labelledby`;
- таблица характеристик содержит `caption`, заголовки `th` с `scope` и адаптивный контейнер;
- основной текст, ссылки и кнопки используют цвета из исходной палитры проекта.

### Ручная проверка с клавиатуры

Перед сдачей вручную пройти все страницы клавишей Tab и проверить видимость фокуса, логичный порядок перехода, ссылки меню, форму заявки, кнопку открытия модального окна и кнопку его закрытия. Также проверить заполнение полей и отсутствие фокуса на скрытых элементах.

### Lighthouse

Необходимо выполнить аудит категории Accessibility минимум для:

- `index.html`;
- `catalog.html`;
- `order.html`.

Порядок выполнения:

1. Запустить сайт локально через Live Server в Visual Studio Code.
2. Открыть страницу в Google Chrome.
3. Открыть DevTools клавишей F12 и перейти на вкладку Lighthouse.
4. Оставить категорию Accessibility и запустить проверку.
5. Изучить найденные проблемы, исправить их и повторить аудит.
6. Сохранить HTML-отчёт или скриншот в папку `lighthouse/` под именем `accessibility-report.html` или `accessibility-report.png`.

Фактический Lighthouse-отчёт ещё не добавлен. Папка `lighthouse/` содержит служебный файл `.gitkeep` до сохранения настоящего результата проверки. Баллы Lighthouse не указываются до выполнения аудита.
